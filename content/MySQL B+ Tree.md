B+树是一种高度平衡的多路查找树，能有效降低磁盘的IO次数，并且支持**有序遍历**和**范围查询**。
![[B+ Tree 1.png]]
- InnoDB采用B+树作为索引，B+树中的每个节点都是一个数据页
- 只有叶子节点才存放了数据，非叶子节点仅用来存放目录项作为索引
- 非叶子节点分为不同层次，通过分层来降低每一层的搜索量
- 所有节点按照索引键大小排序，构成双向链表，便于范围查询
# 与B树的比较
B树和B+树都是多路平衡查找树，主要用于磁盘、SSD等外存储设备。

与普通二叉搜索树相比，B树允许一个节点存储多个键，并拥有多个子节点。这样可以增加树的分支数量、降低树的高度，从而减少查询过程中需要访问的磁盘页数量。

一棵M阶B树中的节点最多拥有M个子节点，M称为B树的阶。

1. 结构差异
	- B树
		- 叶子节点和非叶子节点都可以存储键以及对应的数据记录。
		- 查找到某个键时，可能在非叶子节点直接获得对应数据。
	- B+树
		- 非叶子节点只存储键以及指向子节点的指针，用于索引和导航。
	    - 所有数据记录都存储在叶子节点中。
	    - 叶子节点按照键的顺序通过链表连接，形成一个有序序列。
2. 等值查询
	- B树：
		- 数据可能存储在非叶子节点中，因此查询可能在到达叶子节点之前结束。
		- 单次查询路径可能比B+树短。
	- B+
		- 所有查询最终都需要到达叶子节点。
		- 由于非叶子节点不存储完整数据，一个节点可以容纳更多索引项，因此B+树的分支因子通常更大、树高通常更低。
		- 虽然查询必须到达叶子节点，但并不意味着实际磁盘I/O一定比B树更多。
3. 范围查询
    - B树
	    - 数据分散在叶子节点和非叶子节点中。
	    - 范围查询通常需要在树中进行多次查找或中序遍历，访问路径相对复杂。
    - B+树
	    - 所有数据都集中在叶子节点中，并按照键的顺序排列。
	    - 找到范围起点后，可以沿着叶子节点之间的链表顺序遍历，直到超出查询范围。
	    - 因此B+树非常适合范围查询、排序查询和顺序扫描。
4. 存储效率
	- B树
		- 非叶子节点既需要存储键和子节点指针，也可能存储对应的数据。
		- 单个磁盘页能够容纳的索引项相对较少。
    - B+树
	    - 非叶子节点只存储键和子节点指针，不存储完整的数据记录。
	    - 在磁盘页大小相同的情况下，单个非叶子节点可以容纳更多索引项。
	    - 这会增加树的分支数量、降低树的高度，从而减少磁盘I/O。

	需要注意的是，B+树中的键可能同时出现在非叶子节点和叶子节点中，因此从整个数据结构来看，键本身可能存在一定程度的重复。

5. 插入和删除
    - B树
	    - 数据可能存储在树的不同层级。
		- 插入和删除时，可能涉及键和数据记录在节点之间的移动，同时也可能发生节点分裂、合并和重新平衡。
    - B+树
	    - 数据记录统一存储在叶子节点中。
		- 插入和删除主要发生在叶子节点，但也可能引起节点分裂、合并，并将索引变化传播到父节点。
		- B+树的操作并不一定比B树简单，但数据统一存放在叶子节点，使其结构和查询行为更加稳定。
6. 应用场景
    - B树
	    - 适合需要在内部节点直接存储并查找数据的场景。
		- 某些文件系统或存储结构会使用B树或它的变种。
    - B+树
		- 适合数据库索引和文件系统索引。
		- 特别适用于范围查询、排序、分页、顺序遍历等场景。
		- MySQL InnoDB的索引结构就是B+树。
